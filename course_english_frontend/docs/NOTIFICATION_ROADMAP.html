2. Phase 1 — Chi tiết triển khai

Phạm vi Phase 1
  • Trigger: chỉ publish (DRAFT → PUBLISHED, hoặc republish sau unpublish)
  • Người nhận: HS enrollment.status = ACTIVE cùng classroom của subject bài học
  • Kênh: in-app (bảng + chuông FE, poll 60s)
  • Không làm: email, WebSocket, Redis, RabbitMQ, notify update/unpublish

2.1 Luồng nghiệp vụ

GV POST /lessons/{id}/publish │ ├─► MySQL: status = PUBLISHED ├─► @Async: fan-out INSERT notifications └─► Response 200 (< 300ms) HS GET /notifications (poll 60s) │ ├─► Badge unread-count └─► Click item → /student/lessons/{slug}

2.4 Fan-out publish

1. Load Lesson + Subject + Classroom
2. enrollments = ACTIVE trong classroom
3. title  = "Bài mới: " + lesson.title
   body   = subjectName + " · " + classroomName
   link   = "/student/lessons/" + lesson.slug
4. Batch INSERT (100 rows/lần)
5. Chỉ khi previousStatus != PUBLISHED

2.7 Acceptance criteria

  • GV publish → HS enrolled có row LESSON_PUBLISHED trong ≤ 30s
  • HS không enrolled → không có notify

  • Chuông hiển thị badge; click mở đúng /student/lessons/{slug}

4. Phase 2 — WebSocket (kế hoạch chi tiết)

Mục tiêu — HS online nhận notify ngay khi GV publish (badge + toast), không chờ poll 60s. DB notifications vẫn là nguồn sự thật; WebSocket chỉ push UX.

4.1 Luồng

GV publish │ ├─► INSERT notifications (Phase 1, giữ nguyên) ├─► Email async (Phase 1.5, giữ nguyên) └─► NotificationPushService.pushToOnlineUsers(userIds, payload) HS FE (sau login) │ ├─► WS connect + JWT auth ├─► Nhận event NOTIFICATION_CREATED → bump badge + prepend item └─► Poll 60s vẫn chạy (fallback khi socket disconnect)

4.2 Backend

Thành phầnMô tả

4.5 Acceptance criteria

  • HS tab mở + online → badge tăng trong ≤ 3s sau publish (không cần F5)
  • HS offline → vẫn thấy notify khi mở app (DB + poll/refresh)
  • Socket disconnect → poll fallback vẫn hoạt động
  • Chỉ user nhận fan-out mới được push (đúng userId JWT)
  • Không breaking API REST Phase 1

5. Phase 3 — Redis

  • Cache lesson:detail:{id} + evict khi publish/update block
  • Tách khỏi notification — giảm tải DB khi nhiều HS mở bài mới

6. Phase 4 — RabbitMQ

  • Exchange course.events, routing lesson.published
  • Worker fan-out + EmailWorker retry + DLQ
  • Giữ nguyên schema Phase 1 và API FE
Ghi chú — Phase 1 thiết kế payload linkPath + type enum cố định để Phase 2–4 plug-in mà không breaking change.
