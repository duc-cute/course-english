10. SWOT, rủi ro & anti-pattern

Anti-pattern: “PDF Viewer + bài tập”

Lesson = HTML dài + file đính kèm, không quiz/audio/checkpoint → HS chỉ scroll và đánh dấu xong.

Phòng tránh: block QUIZ bắt buộc; audio checkpoint; rule hoàn thành (ví dụ ≥80% quiz đúng); progress có nghĩa trên server.

Điểm mạnh

  • Block lesson + CMS + reader đã chạy
  • JWT, lớp, enrollment
  • Theme HS/Admin tách

Điểm yếu / rủi ro

  • Chưa quiz/assignment
  • Progress local only
  • Publish chưa filter lớp
  • Scope creep (AI trước quiz cơ bản)

Ví dụ bài “Fruits” (promt.md)

Lesson: Fruits
  1. VOCABULARY        → Apple, Banana, Orange (+ image, audio)
  2. FLASHCARD         → sourceVocabularySetId
  3. MATCH_IMAGE       → questions[]
  4. SPELLING          → missing letter / type word
  5. LISTEN_CHOOSE     → audio → chọn đáp án
  6. GRAMMAR_RULE      → rule + ví dụ
  7. QUIZ              → mini assessment
  8. SUMMARY           → key phrases
Một bài tiểu học = Input (content) → Practice (interactive blocks) → Check (quiz) → Reflect (summary).

blockTypepayload (data) — gợi ý schema
TEXT{ "html": string }
IMAGE{ "assetId", "caption" }
VIDEO / AUDIO{ "assetId", "transcript?", "autoplay?" }
PDF{ "assetId" } — type FILE
VOCABULARY{ "words": [{ word, meaning, image, audio }] }

MATCH_IMAGE{ "questions": [{ prompt, options[], correctId }] }

QUIZ{ "quizId" } hoặc inline questions[]
SUMMARY{ "items": string[] }

13.5 Senior EdTech review

Điểm mạnh (đã đúng hướng)

  • lesson_blocks + payload_json = plugin architecture sẵn.
  • Tách LessonAsset — media tái sử dụng nhiều block.
  • Reorder block, publish flow, reader có TOC.

Điểm yếu cần sửa

  • Enum Java 7 loại — chặn thêm FLASHCARD, MATCH_IMAGE không migration.
  • FE switch if blockType — chưa registry, khó scale 30+ block.
  • Không lesson_block_progress — interactive block không có ý nghĩa.
  • Editor chỉ TEXT/IMAGE — taxonomy promt chưa vào UI.

Cải tiến đề xuất (thứ tự)

  1. S0: Mở block_type VARCHAR + document schema từng type (OpenAPI / Zod).
  2. S1: Hoàn thiện CONTENT (AUDIO, VIDEO, PDF) + TEACHING cơ bản.
  3. S2: FE BLOCK_REGISTRY + progress API từng block.
  4. S3+: VOCAB PRACTICE → GRAMMAR PRACTICE → ASSESSMENT → SPEAKING (V3).
  5. S8: Drag-drop Lesson Builder cho giáo viên.

15. Hạ tầng V2 — Redis, RabbitMQ & WebSocket (sau Lesson)

15.5 Luồng tích hợp — ví dụ publish lesson

GV POST /lessons/{id}/publish
    │

    ├─► Redis: EVICT lesson:detail:{id} + syllabus
    ├─► RabbitMQ: publish lesson.published
    └─► Response 200 (ngay)

RabbitMQ → NotificationWorker
    │

    ├─► FOR each student:
    │       INSERT notifications (user_id, type, title, link, read=false)
    │       optional: queue notification.email (1 message / user)
    │       IF online: WebSocket push
    └─► EmailWorker: SMTP (retry 3x → DLQ)

16.2 Công thức Risk Score

Risk Score = tổng điểm cộng dồn từ 4 tín hiệu (gợi ý cap 100). HS có score < 20 không xuất hiện trong danh sách “cần hỗ trợ”.

Không hoạt độnginactiveDays > 7 (strict, không tính ngày thứ 7)+50INACTIVE_7D
Thiếu bài≥ 1 lesson OVERDUE (due_at < now, chưa passed)+30MISSING_ASSIGNMENTS
Điểm thấpTrung bình best score bài tập < 60%+25LOW_AVG_SCORE
Tụt điểmTB 3 bài gần nhất − TB 3 bài trước đó ≤ −15%+20SCORE_DECLINE

16.3 Định nghĩa kỹ thuật từng tín hiệu

16.3.1 Last activity — inactiveDays

lastActivityAt = MAX(
  lesson_reading_progress.updated_at,
  lesson_practice_attempts.completed_at
) trên mọi lesson PUBLISHED thuộc lớp HS

Nếu chưa có activity → lastActivityAt = enrollment.joined_at

inactiveDays = số ngày (ChronoUnit.DAYS) từ lastActivityAt đến now
Rule +50 khi inactiveDays > 7

16.3.2 Missing assignments — missingCount (cần lessons.due_at)

GV gán Hạn nộp khi publish/sửa lesson. Lesson không có due_at → không tính missing.

eligible = lesson PUBLISHED + due_at IS NOT NULL + thuộc lớp HS ACTIVE

OVERDUE (thiếu / quá hạn):
  due_at < now AND không có attempt với passed = true
  → missingCount++, risk +30 (một lần nếu có ≥1 OVERDUE)

UPCOMING (chưa làm, còn hạn):
  due_at >= now AND chưa passed
  → KHÔNG tính risk, KHÔNG vào missingCount
  → chỉ hiện trong popup View Profile

16.3.3 Average score — avgScorePercent

Với mỗi lesson có ít nhất 1 attempt: lấy best score_percent
avgScorePercent = trung bình các best score
(Lesson chưa có attempt → bỏ qua, không tính 0)

Rule +25 khi avgScorePercent < 60

16.3.4 Score trend — scoreTrendPercent

Sắp xếp lesson theo thời gian attempt gần nhất
recentAvg  = TB best score của 3 bài gần nhất (có điểm)
previousAvg = TB best score của 3 bài ngay trước đó
scoreTrendPercent = recentAvg - previousAvg   (âm = tụt)

Rule +20 khi scoreTrendPercent <= -15

16.3.5 Reason label (hiển thị 1 dòng trên card/bảng)

Ưu tiên lý do có điểm risk cao nhất, ghép tối đa 2:

  • Inactive + Missing Homework
  • Low Performance
  • Score dropped: -15%
